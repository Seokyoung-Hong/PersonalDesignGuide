# 원칙 2. Easy to Answer

> 사용자에게 쉽게 대답할 수 있는 질문만 한다.
> 사용자가 모르는 것은 시스템이 판단한다.

여기서 "질문"은 설문 문장만이 아니다.
**선택 화면, 버튼, 옵션, 동의 과정 모두 사용자에게 던지는 질문**이다.

```text
[전문가 도움받기]  [직접 신청하기]
```

이 화면은 사실상 "어떤 방식으로 진행하시겠습니까?"라고 묻고 있다.
문제는 사용자가 두 방식의 차이와 이후 과정을 모르면 **대답할 수 없다**는 것.

## 규칙 1. 사용자가 아는 것을 질문한다

시스템 구조에 대한 판단을 사용자에게 넘기지 않는다.
사용자는 자신의 **현재 상태**는 알지만, 시스템의 **경로별 차이**는 모른다.

```text
❌ 어떤 청구 방식을 선택하시겠어요?
   - 전문가 상담
   - 직접 청구
   (→ 각 경로의 장단점과 준비물을 사용자가 알 수 없음)

✅ 청구 서류를 준비했나요?
   - 네, 준비했어요
   - 아직 없어요
   (→ 답을 바탕으로 경로 선택은 시스템이 담당)
```

## 규칙 2. 미래를 예측해야 하는 질문을 피한다

선택 이후의 결과를 모르면 쉽게 답할 수 없다.

```text
❌ [기본 설정]  [고급 설정]
   (→ 처음 쓰는 사람은 무엇이 적절한지 판단 불가)

✅ [권장 설정으로 시작하기]  [직접 설정하기]
   (→ 시스템이 기본값을 추천, 원하면 직접 제어)
```

예측이 불가피하다면 각 선택지에 결과 미리보기나 상세 설명을 붙인다.

## 규칙 3. 추상적인 선호보다 구체적인 사실을 묻는다

```text
❌ 어떤 금융 상품을 선호하시나요?
   (→ 상품 분류 + 자기 선호를 먼저 정리해야 답할 수 있음)

✅ 이 돈은 언제 사용할 예정인가요?
   - 언제든 꺼내 쓸 수 있어야 해요
   - 1년 이상 보관할 수 있어요
   (→ 실제 상황을 물으면 상품 매칭은 시스템이 함)
```

## 규칙 4. 선택지의 기준을 통일한다

같은 질문에 대한 답은 같은 축으로 구성한다.

```text
❌ - 빠른 배송      (속도 축)
   - 직접 수령      (수령 방식 축)
   - 저렴한 배송    (가격 축)

✅ 수령 방법
   - 일반 배송
   - 빠른 배송
   - 직접 수령
   (가격 차이는 각 항목의 부가 정보로 표시)
```

## 규칙 5. 3초 룰

**3초 안에 답이 나오지 않으면 어려운 질문이다.**
(과학적 법칙이 아니라 실무 검토 기준)

답변이 3초를 넘기는 신호:

- 질문이 모호하다
- 선택지 간 차이가 불명확하다
- 필요한 정보가 화면에 없다
- 사용자가 기억을 더듬어야 한다
- 선택 결과가 예상되지 않는다
- 무엇이 자신에게 유리한지 계산해야 한다

## 규칙 6. 시스템이 알 수 있다면 묻지 않는다

시스템이 이미 가진 정보를 사용자가 다시 찾아서 답하게 하지 않는다.

- 주소를 알면 → 지역을 다시 선택하게 하지 않는다
- 계정 정보를 알면 → 이메일을 다시 입력받지 않는다
- 주문 정보를 알면 → 주문번호를 직접 찾게 하지 않는다
- 가입 상품을 알면 → 전체 목록에서 찾게 하지 않는다 (가입한 것만 보여준다)

질문을 없앨 수 없다면, 가진 데이터로 **선택지를 줄여서** 보여준다.

## 셀프 체크

- [ ] 사용자가 이 질문의 답을 실제로 알고 있는가?
- [ ] 답하려면 전문 지식이나 시스템 이해가 필요하지 않은가?
- [ ] 선택 이후의 결과를 예측할 수 있는가?
- [ ] 선택지가 같은 기준(축)으로 구성됐는가?
- [ ] 시스템이 대신 판단할 수 있는 질문은 아닌가?
- [ ] 이미 가진 데이터로 선택지를 줄일 수 있는가?
- [ ] 질문을 구체적인 사실 확인으로 바꿀 수 있는가?
- [ ] 3초 안에 선택할 수 있는가?
