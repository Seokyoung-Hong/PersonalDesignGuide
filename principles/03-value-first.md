# 원칙 3. Value First, Cost Later

> 사용자에게 비용을 요구하기 전에, 그 행동으로 얻을 가치를 먼저 보여준다.

사용자는 화면을 보는 순간 의식적이든 무의식적이든 이렇게 계산한다.

```text
얻게 되는 가치 ≥ 요구받는 비용인가?
```

- 가치가 불분명하면 → 아주 작은 비용도 크게 느껴진다
- 결과가 구체적으로 보이면 → 어느 정도의 절차는 감수한다

## "비용"은 돈만이 아니다

사용자가 지불하는 비용의 목록:

시간 · 정보 입력 · 회원가입 · 본인 인증 · 개인정보 제공 · 권한 허용 · 긴 대기 ·
학습 · 결제 · 약관 동의 · 심리적 부담 · 새로운 습관 형성

## 규칙 1. 행동 설명과 가치 설명은 다르다

```text
❌ 보험 조회하기
   (→ 무엇을 해야 하는지는 알지만, 왜 해야 하는지는 모름)

✅ 내 보험료가 또래보다 많은지 확인해 보세요.
   (→ 행동의 목적을 이해할 수 있음)
```

버튼·진입점 문구를 쓸 때 항상 물어본다: **이건 행동을 설명하는가, 가치를 설명하는가?**

## 규칙 2. 가치는 구체적이어야 한다

추상적인 혜택은 설득력이 없다.

```text
❌ 더 나은 금융 경험을 만나보세요.
✅ 흩어진 계좌와 카드 지출을 한 화면에서 확인하세요.
```

가장 강력한 방법은 **결과 자체를 미리 보여주는 것**이다.

```text
✅ (예시 데이터로 결과 화면 미리보기)
   이번 달 고정 지출
   통신비   55,000원
   구독료   29,000원
   보험료  103,000원
```

토스 사례: 보험 조회의 인증 절차를 줄일 수 없자, 조회 시작 전에 "또래와
보험료·보장 수준 비교" 결과 화면을 예시 데이터로 먼저 보여줬다.
→ 조회 완료율이 기존 대비 67% 상승.

## 규칙 3. 비용이 클수록 가치는 더 명확해야 한다

사용자가 느끼는 비용이 커지는 신호:

- 질문이 3~4개 이상 이어진다
- 5초 안에 답하기 어려운 질문이 있다
- 까다로운 비밀번호 조건이 있다
- 바로 기억하기 어려운 정보(이메일 등)를 요구한다
- 연봉 같은 민감한 정보를 요구한다

따라서 아래 화면에서는 가치 설명이 **특히** 중요하다:

회원가입 · 신원 인증 · 외부 계정/데이터 연결 · 알림 허용 · 위치 권한 ·
연락처 접근 · 결제수단 등록 · 유료 구독 전환 · 장문의 신청서 · 민감정보 입력

## 규칙 4. 가치 제시는 과장이나 기만이 아니다

Value First는 비용을 **숨기라는** 뜻이 아니다. 아래는 잘못된 적용이다.

- 결제 사실을 뒤에 숨김
- 자동 갱신 조건을 작게 표시
- 결과를 보장하는 것처럼 표현
- 개인정보 사용 범위를 축소해 표현
- 무료 체험 종료 후 과금 사실을 감춤
- 가치만 강조하고 위험·제한을 누락

올바른 정보 제시 순서:

```text
1. 사용자가 얻는 가치
2. 이를 위해 필요한 행동
3. 요구하는 정보와 이유
4. 발생하는 비용과 조건
5. 사용자가 취소하거나 거부할 방법
```

## 규칙 5. 화면을 추가하는 것이 오히려 단순할 수 있다

화면 수가 적다 ≠ 경험이 단순하다.

토스는 조회 절차 **앞에** 가치 설명 화면을 하나 추가했다. 단계는 늘었지만
사용자는 왜 조회해야 하는지, 어떤 결과를 얻는지, 긴 절차를 거칠 가치가 있는지를
이해하게 됐다.

단계 추가를 검토할 상황:

- 긴 절차 앞에서 이탈이 많을 때 → 가치 미리보기 화면 추가
- 민감 정보 입력 앞 → 사용 목적 설명 추가
- 파괴적 행동 앞 → 결과 안내 추가

## 셀프 체크

- [ ] 사용자가 이 행동을 해야 할 이유를 알고 있는가?
- [ ] 얻는 결과를 구체적으로 상상할 수 있는가?
- [ ] 가치보다 입력·인증이 먼저 등장하지 않는가?
- [ ] 비용의 크기에 비해 가치 설명이 충분한가?
- [ ] 예시 화면·미리보기로 결과를 보여줄 수 있는가?
- [ ] 가치가 추상적인 홍보 문구에 머물지 않는가?
- [ ] 비용과 제한 조건도 정직하게 공개하는가?
