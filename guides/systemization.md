# 가이드: UX 문제를 재사용 가능한 시스템으로 만든다

> 좋은 UX를 개인의 감각이나 기억에 맡기지 않는다.
> 반복되는 문제는 원칙 → 규칙 → 템플릿 → 컴포넌트 → 자동 검증으로 승격시킨다.

## 왜 문서만으로는 부족한가

문서만 존재하면:

- 문서의 존재를 모른다
- 필요할 때 찾지 않는다
- 규칙은 알아도 직접 작성하기 어렵다
- 해석이 사람마다 다르다
- 바쁘면 기존 방식으로 돌아간다
- 디자인과 코드에 서로 다른 표현이 적용된다

**원칙은 실제 작업 도구(컴포넌트, 템플릿, 린트) 안에 들어가야 지켜진다.**
토스는 오류 메시지 기준을 문서로만 두지 않고, 컴포넌트를 불러올 때
자주 쓰는 문구 템플릿을 함께 선택할 수 있게 만들었다.

## 시스템화의 5단계

문제를 발견하면 가능한 한 높은 단계까지 끌어올린다.

### 1단계: 원칙

```text
사용자가 해결 방법을 알 수 있게 쓴다.
```

### 2단계: 작성 규칙

```text
원인 + 해결 행동 순서로 작성한다.
기술 코드와 내부 용어를 노출하지 않는다.
```

### 3단계: 템플릿

```text
{원인} 때문에 {작업}하지 못했어요.
{해결 행동}해 주세요.
```

### 4단계: 컴포넌트

```tsx
<ErrorMessage
  reason="인증 시간이 지났어요."
  action="다시 인증해 주세요."
/>
```

### 5단계: 자동 검증

- 금지 용어 검사
- 누락된 접근성 레이블 검사
- 버튼 문구 길이 검사
- 허용되지 않은 컴포넌트 조합 검사

## 개별 문제를 공통 규칙으로 승격시키는 흐름

```text
개별 사용성 문제 발견
→ 원인 분석
→ 다른 화면에서도 반복되는지 확인
→ 공통 원칙 도출
→ 디자인 시스템 / 가이드에 반영
→ 신규 화면에 자동 적용
```

### 예시

발견된 문제:

```text
사용자가 휴지통 아이콘을 보관 기능으로 오해한다.
```

❌ 잘못된 대응 — 해당 화면의 아이콘만 수정한다.

✅ 더 나은 대응:

- 삭제 행동에는 텍스트 레이블을 함께 제공한다
- 영구 삭제와 임시 보관을 구분한다
- 파괴적 행동에 동일한 색상과 확인 방식을 적용한다
- 아이콘 단독 사용 조건을 디자인 시스템에 명시한다
- 모든 기존 화면을 점검한다

## 사용자 조사 결과의 반영

특정 화면에서 발견한 문제를 그 화면 하나만 고치지 말고,
디자인 시스템과 라이팅 가이드에 반영한다.

토스 사례: 시니어 사용자 연구에서 질문형 버튼 문구가 오해를 일으킬 수 있음을
발견 → 해당 기준을 디자인 시스템 가이드에 반영, 공통 리스트 레이아웃 개선 검토.

## 나의 실천 규칙

- **같은 문제를 두 번 발견하면** 개별 수정에 그치지 않고 이 가이드에 규칙으로 기록한다
- 새 규칙은 가능하면 템플릿이나 컴포넌트 형태까지 만든다
- 코드로 검증 가능한 규칙(문구 길이, 금지 용어)은 린트/테스트로 자동화한다
