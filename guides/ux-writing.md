# 가이드: UX Writing

> 화면 구조가 좋아도 문구가 잘못되면 사용자는 행동하지 못한다.
> 문구는 감각이 아니라 원칙 → 규칙 → 템플릿으로 관리한다.

## 작성 원칙

```text
쉽고 구체적으로 쓴다.
```

## 작성 규칙

1. 한 문장에 한 가지 정보만 쓴다
2. 사용자가 해야 할 행동을 동사로 표현한다
3. 내부 용어·기술 코드를 노출하지 않는다
4. 불필요한 명사화를 줄인다 ("연동 절차를 진행합니다" → "연결해요")
5. 오류는 원인과 해결 방법을 함께 제공한다
6. 민감한 상황(결제 실패, 거절, 인증 실패)에서는 장난스러운 표현을 피한다

## 1. 버튼 — 결과를 예측할 수 있게

"확인"은 맥락에 따라 저장·결제·삭제·제출·동의 무엇이든 될 수 있다.
버튼은 **구체적인 행동**을 표현한다.

```text
❌ 확인
✅ 변경 내용 저장 / 결제하기 / 계정 삭제 / 신청서 제출 / 약관에 동의하고 계속
```

## 2. 용어 — 하나의 대상, 하나의 이름

같은 대상을 여러 이름으로 부르지 않는다.

```text
❌ 회원 / 사용자 / 고객 / 이용자 (혼용)
✅ 기준 용어를 하나 정하고 전체에서 통일
```

프로젝트마다 **용어 사전(glossary)** 을 만들어 기준 용어를 기록한다.

## 3. 보이스톤 — 하나의 제품처럼 들리게

상황에 따라 말투가 널뛰지 않아야 한다.

```text
❌ 성공: 처리 완료!
   오류: 오류가 발생하였습니다.
   알림: 확인해보실래요? 😊
   (→ 문체와 정서가 제각각이면 하나의 제품처럼 느껴지지 않음)

✅ 기준 톤을 정하고(예: 해요체, 차분하고 명확하게) 모든 문구에 적용
```

## 4. 오류 메시지 — 사실이 아니라 회복 방법을

오류 사실만 알리지 말고, 무엇이 잘못됐고 어떻게 해결하는지 알려준다.

### 템플릿

```text
{원인} 때문에 {작업}하지 못했어요.
{해결 행동}해 주세요.
```

### 상황별 프리셋

```text
입력 누락:    {항목명}을 입력해 주세요.
형식 오류:    {항목명}을 다시 확인해 주세요.
네트워크 오류: 연결이 불안정해요. 잠시 후 다시 시도해 주세요.
인증 만료:    인증 시간이 지났어요. 다시 인증해 주세요.
```

### 금지 사항

- 기술 코드 노출 (`Error 500`, `NullPointerException`)
- 사용자 탓하기 ("잘못 입력하셨습니다")
- 해결 방법 없는 통보 ("오류가 발생했습니다")

## 5. 안내 문구 — 행동 + 이유 + 결과를 한 문장에

```text
❌ 서비스 이용을 위한 개인 식별 정보 연동 절차를 진행합니다.
✅ 내 보험을 불러오려면 본인 인증이 필요해요.
```

## 6. 길이와 레이아웃

문구가 컴포넌트에 맞지 않아 잘리는 문제도 문구 시스템에서 관리한다.

- 버튼 레이블 최대 길이를 정한다
- 긴 문구는 디자인 단계에서 최대 길이 케이스로 검증한다

## 관리 대상 컴포넌트

- Button label
- Input helper / placeholder
- Error message
- Dialog title / body
- Empty-state description
- Push notification / 알림

## 셀프 체크

- [ ] 버튼 문구만 읽어도 누르면 무슨 일이 생기는지 알 수 있는가?
- [ ] 같은 대상을 부르는 이름이 하나로 통일됐는가?
- [ ] 오류 메시지에 원인과 해결 방법이 모두 있는가?
- [ ] 내부 용어·기술 코드가 노출되지 않는가?
- [ ] 민감한 상황의 문구가 상황에 맞는 톤인가?
- [ ] 가장 긴 문구가 들어가도 레이아웃이 깨지지 않는가?
