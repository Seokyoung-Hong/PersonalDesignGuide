# 출시 전 리뷰 체크리스트

화면·기능을 내보내기 전에 이 목록으로 셀프 리뷰한다.
하나라도 "아니오"면 해당 원칙 문서로 돌아가 설계를 다시 본다.

## 1. Simplicity — 세 가지 비용

### 인지 비용

- [ ] 처음 보는 사용자가 설명 없이 화면의 목적을 3초 안에 파악할 수 있다
- [ ] 전문 용어·내부 용어가 노출되지 않는다
- [ ] 한 화면에 한 가지 목적만 있다
- [ ] 중요한 정보와 부가 정보의 위계가 시각적으로 구분된다
- [ ] 버튼 문구만 읽어도 결과를 예측할 수 있다

### 심리 비용

- [ ] 민감한 정보를 요구할 때 이유와 사용 범위를 밝혔다
- [ ] 되돌릴 수 있는 행동은 되돌릴 수 있다고 명시했다
- [ ] 파괴적 행동 앞에서 결과를 미리 알리고 확인을 받는다
- [ ] 요금·조건·제한을 숨기지 않았다

### 노동 비용

- [ ] 시스템이 이미 아는 정보를 다시 묻지 않는다
- [ ] 합리적인 기본값이 제공된다
- [ ] 중간에 이탈해도 이어서 진행할 수 있다
- [ ] 불필요한 확인 단계가 없다

## 2. Easy to Answer — 모든 질문과 선택지

- [ ] 사용자가 이 질문의 답을 실제로 알고 있다
- [ ] 시스템 구조에 대한 판단을 사용자에게 요구하지 않는다
- [ ] 선택 이후의 결과를 예측할 수 있다
- [ ] 선택지가 같은 기준(축)으로 구성됐다
- [ ] 이미 가진 데이터로 선택지를 줄였다
- [ ] 모든 질문에 3초 안에 답할 수 있다

## 3. Value First, Cost Later — 비용을 요구하는 모든 지점

- [ ] 가치 설명이 비용 요구보다 먼저 나온다
- [ ] 가치가 구체적이다 (추상적 홍보 문구 ✗)
- [ ] 가능하면 결과를 미리보기로 보여준다
- [ ] 비용이 큰 화면(가입·인증·권한·결제)일수록 가치 설명이 강하다
- [ ] 비용·조건·취소 방법을 정직하게 공개한다

## 4. UX Writing

- [ ] "확인" 같은 모호한 버튼이 없다 — 모든 버튼이 구체적 행동을 표현한다
- [ ] 용어가 하나로 통일됐다
- [ ] 보이스톤이 일관된다
- [ ] 오류 메시지에 원인 + 해결 방법이 있다
- [ ] 민감한 상황(실패·거절)의 문구 톤이 적절하다
- [ ] 가장 긴 문구에서도 레이아웃이 깨지지 않는다

## 5. 시스템화

- [ ] 이번에 발견한 문제 중 다른 화면에서도 반복될 것이 있는가 확인했다
- [ ] 반복될 문제는 가이드/템플릿/컴포넌트로 승격시켰다

## 빠른 버전 (시간이 없을 때 이 5개만)

1. 설명 없이 3초 안에 이해되는가?
2. 사용자가 모르는 것을 묻고 있지 않은가?
3. 가치가 비용보다 먼저 보이는가?
4. 버튼을 누르면 무슨 일이 생기는지 예측되는가?
5. 오류가 나면 사용자가 스스로 회복할 수 있는가?
